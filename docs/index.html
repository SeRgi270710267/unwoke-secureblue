unwoke-secureblue

A security-focused Fedora Atomic desktop: secureblue’s hardening, with Brave Origin and no curator store.

Get the overlay

Not affiliated with secureblue. This is a personal overlay on their signed images. Stock secureblue is at secureblue.dev.

About

unwoke-secureblue is a daily BlueBuild overlay on official secureblue Fedora Atomic images. Kernel hardening, SELinux, hardened_malloc, closed firewall, and their ujust commands stay. We only change two product decisions: the house browser and the house app store.

The browser is the standalone Brave Origin RPM (brave-origin), not full brave-browser and not Trivalent. There is no GUI software store. Flathub is a CLI remote. User namespaces stay off for unconfined apps; Brave Origin runs in its own brave_t domain so its Chromium sandbox can start.

It is shipped as OCI bootable container images. Rebase onto one of them from secureblue or any Fedora Atomic desktop. For details, see the features list.

Their hardening

Kernel args, SELinux, hardened_malloc, no Xwayland by default, USBGuard, run0. Inherited, not reimplemented.

Brave Origin

Standalone RPM. Compiled-out extras. Default browser. Not Trivalent, not full Brave.

No curator store

Bazaar, GNOME Software, and Plasma Discover are gone. Use the terminal: flatpak, brew, rpm-ostree.

Who this is for

People who already want Linux, already want secureblue’s hardening, and do not want Trivalent or a curated app catalog deciding which browsers exist.

This is not as locked down as stock secureblue + Trivalent. If maximum desktop confinement is your first priority, use stock secureblue. If you want their kernel and SELinux with Brave Origin and a terminal-only install path, this overlay is for you.

Honest limits

  • Brave Origin is not Trivalent. No Vanadium-style Chromium patches, no tight Trivalent SELinux jail.
  • brave_t is an unconfined-like domain on the userns allow-list so the sandbox can start. Other unconfined apps stay blocked.
  • The signing key is a GitHub secret, not a hardware key.
  • We do not rebuild their kernel or re-run their SLSA pipeline. We inherit whatever they already shipped, after checking their signature.
