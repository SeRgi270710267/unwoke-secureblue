Features

Most of the security story is still secureblue’s. This page is the delta, plus what we keep.

Inherited from secureblue

We layer on their already-built, already-signed images. We do not reimplement these:

  • hardened_malloc globally, including Flatpaks.
  • Kernel hardening via sysctl and kernel arguments, with their ujust set-kargs-hardening.
  • SELinux enforcing. Unprivileged user namespaces off for the unconfined domain, on for Flatpak.
  • Xwayland off by default. GNOME user extensions off. KDE GHNS off.
  • sudo / su / pkexec replaced with run0 on their images. SUID stripped from many binaries.
  • USBGuard with their ujust helpers. firewalld closed by default. NTS for time. HTTPS rpm mirrors.
  • Automatic updates. Their full ujust surface still works.

Read their list if you want the complete inventory. We did not gut SELinux, kernel args, disk encryption, or Secure Boot enrollment.

Brave Origin

Not full brave-browser. The Origin package is a separate RPM with extras compiled out, installed under /opt/brave.com/brave-origin/. Policies live in /etc/brave-origin/policies/managed/.

brave_t is an unconfined-like domain so the browser can actually run. It is not Trivalent’s tight jail, and you do not get Trivalent’s Chromium patches. Those patches live in their browser source. Brave Origin cannot grow them.

What we can force are Chromium enterprise policies:

  • HTTPS-only, no WebRTC IP leak, no metrics — on by default.
  • JIT-less — optional; breaks some sites.

Overlay ujust extras

Stock secureblue commands still work. Added on top:

ujust unwoke-status
ujust audit-unwoke
ujust set-brave-hardening on
ujust set-brave-hardening off
ujust set-brave-jitless on

Restart Brave Origin after policy changes.

Honest limits

Calling this “insecure Fedora” is false. Calling it “identical to secureblue” is also false. It is weaker than stock + Trivalent and stronger than the earlier overlay that disabled harden_userns globally.

  • No Vanadium-style Chromium patches.
  • Signing key is a GitHub secret, not a hardware key.
  • We inherit their signed image; we do not rebuild their kernel.
